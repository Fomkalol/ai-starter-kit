description: Зафиксировать прогресс по направлению перед сменой аккаунта/сессии — файл-хендофф + память
---

Сессия скоро закончится (смена аккаунта или перерыв). Зафиксируй ВСЁ по теме текущей работы так, чтобы любая новая сессия (в том числе под другим аккаунтом) могла продолжить с этой точки без доступа к этому чату.

Тема хендоффа: $ARGUMENTS (если пусто — определи сам по контексту сессии).

Сделай:

1. **Файл-хендофф** — запиши в `~/ai-workspace/handoffs/<тема>-<дата YYYY-MM-DD>.md`:
   - **Что сделано** в этой сессии (конкретно: файлы, серверы, команды, решения)
   - **Текущее состояние** — что работает, что задеплоено, что наполовину
   - **Точка продолжения** — первый следующий шаг, с которого начинать
   - **Дальнейшие шаги** — план, приоритеты
   - **Артефакты** — пути к файлам, репо, ветки, URL, VM, доступы (без секретов — только где лежат)
   - **Грабли/решения** — неочевидное, что выяснили (чтобы не переоткрывать)
   - **Если хендофф из-за «застрял»** (лимит попыток / стоп-триггер) — добавь пакет: текущий diff или ветка; история попыток (гипотеза → что сделал → результат/симптом); какие тесты падают/проходят и менялись ли симптомы между попытками; причина остановки; следующая НЕпроверенная гипотеза. Не «не получилось», а с чем именно передаёшь.

2. **Память** — обнови соответствующий project-файл в памяти (`~/ai-workspace/memory/`, формат — memory-entry-template.md): новый статус + ссылка на файл-хендоффа. Если файла памяти по направлению нет — создай и добавь строку в MEMORY.md.

3. **TASKS.md** — обнови единый трекер `~/ai-workspace/TASKS.md`: отметь сделанное, перенеси хвосты.

4. **Пуш в GitHub** — синхронизируй, чтобы работа не осталась только на Маке:
   - **Workspace** (`~/ai-workspace`): СНАЧАЛА проверь, что это git-репо с приватным remote (`git remote -v`; видимость репо — приватная; не уверен — спроси пользователя и не пушь). Добавляй только файлы знаний (TASKS.md, handoffs/, memory/, products/) — НЕ `git add -A`. Перед коммитом пробеги добавляемое глазами на секреты. Потом commit и push.
   - **Код-репо, где шла работа**: если есть незакоммиченные правки — покажи `git status`; коммить/пушь ТОЛЬКО с явного ОК и НЕ в main (если на main — сначала ветка). Не пушь чужие/недоделанные правки молча.
   - Если пуш падает (нет сети/remote) — не блокируйся, отметь в резюме, что осталось незапушенным.

5. В ответ выведи короткое резюме: путь к хендоффу + что запушено (и что нет) + фраза, которую сказать новой сессии, чтобы продолжить (например: «Продолжи по ~/ai-workspace/handoffs/<тема>-<дата>.md»).

Пиши сжато, но полно — файл должен быть self-contained.
