# Кросс-ревью: второй агент смотрит твой дифф

Идея: код, написанный одним агентом, перед мержем ревьюит ДРУГАЯ модель (Codex ревьюит
Claude и наоборот). Свежий взгляд без контекста автора ловит то, что автор не видит.
Свои находки ревьюеру заранее не показывай — вердикт должен быть независимым.

## review.sh — быстрое (читает дифф)

Из корня код-репо, нужен установленный ревьюер (`codex` или `claude`):

```bash
sh ~/ai-starter-kit/review/review.sh codex                # дифф текущей ветки против main
sh ~/ai-starter-kit/review/review.sh codex develop fix-x  # база и тема отчёта
```

Отчёт падает в `out/reports/`. Опции через переменные:
`REVIEW_SCOPE="src/auth"` — файлы вне списка = отказ (ловит самовольные правки),
`REVIEW_EXCLUDE="data package-lock.json"` — не тащить в дифф генерируемое.

## review-deep.sh — глубокое (запускает код)

Для рискованного: перед мержем в main, релизом, деплоем, для безопасности/денег/парсинга.
Изолированные клоны, несколько параллельных «финдеров» с правом запускать тесты и repro,
скептики перепроверяют каждую находку исполнением, затем синтез:

```bash
sh ~/ai-starter-kit/review/review-deep.sh          # против main
DEEP_FINDERS=4 sh ~/ai-starter-kit/review/review-deep.sh develop payments
```

Дольше и дороже review.sh — используй по делу. P1/P2 из отчёта чини и повторяй ревью.

## Оплата и подписки

Общий промпт ревью почти никогда не замечает проблемы с покупками (Store ID под другой аккаунт,
устаревший SDK, бэкдор премиума): в диффе «логика не нарушена». Поэтому оба скрипта сами
находят платёжный код в репо (StoreKit, Adapty, RevenueCat, Google Billing, Stripe) и добавляют
обязательный раздел «Оплата»: в review.sh — блок в промпте, в review-deep.sh — седьмой финдер
«Payments», который смотрит весь модуль оплаты, а не только дифф. Что нельзя проверить по коду
(реальная покупка, конфиг в дашборде), ревьюер перечисляет явно — это остаётся на TestFlight/девайс.
