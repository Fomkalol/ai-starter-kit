# Нейминг: методология

Цель — качественный бренд для целевой аудитории, а не подгон под чей-то вкус. Порядок жёсткий: генерация широко → дешёвые фильтры → дорогие проверки только финалистам → скоринг → человеческий тест.

## 1. Генерация (20-30 кандидатов, не влюбляться в первого)

Техники: сленг ниши (slab, photo dump), реальные короткие слова, усечения/компрессии (Pullr, PSTR), дабл-буквы (Slabb), составные (FaxDove), слова из языков аудитории. Требование на входе: **бренд ≤10 символов** (см. бюджет title ниже) и слогов ≤3.

Анти-урок из портфеля юзера: consonant-компрессии (PSTR) дают spelling-риск, слабый голосовой CTA и коллизии с тёзками — не запрещены, но проверяются строже.

## 2. Дешёвые фильтры (все кандидаты, минуты)

- **Домены** (RDAP): .com/.app — заняты кем? Парковка ≈ ок (флаг «можно купить»), живой продукт ≈ сильный минус.
- **Поиск в сторе**: `itunes.apple.com/search?term=<имя>&entity=software` + Play-поиск (браузерный UA) — тёзки/гиганты по префиксу? Это ОТДЕЛЬНАЯ выдача от Google.
- **Google SERP**: «имя», «имя app» — кто владеет; если владелец — крупный бренд с соцсетями/ритейлом, запрос не отнять никогда (кейс pstr → PSTR Studio 583K IG).
- **Соцхэндлы**: tiktok.com/@имя, instagram.com/имя — для УБТ хэндл = бренд в голосовом CTA.
- **Кросс-язычный чек**: приоритет — английский (US + tier-1): значение, произносимость, ассоциации. Второстепенные гео трафика (PH/ID/BR/MX…) — проверить, но проблема там = флаг с пометкой, НЕ стоп.

## 3. Дорогие проверки (только 3-5 финалистов)

**Приоритет №1 — живой тёзка-конкурент в сторе.** Это главный практический veto, и проверять его надо тщательнее всего (не только точное имя, но и с суффиксами/раскладками). Пример из практики: GPT предлагал HoloDex ⭐⭐⭐⭐⭐ — а он уже живёт в App Store с тучей установок (id6747442689). Живой тёзка с трафиком дороже любого формального TM-нюанса: каннибализация ASO, путаница, отзывы утекают к нему.

- **TM** (tmdn.org): классы 9/42, юрисдикции EM/US/GB + гео трафика; похожие знаки, не только точные; TMview лагает на свежих заявках пару дней — пере-чек перед финальным коммитом.
- **Франшизные и любые чужие знаки проверяются одинаково.** Чужой бренд (Pokemon/Nintendo/Disney/Marvel и т.п.) в имени — это риск отказа/удаления по правилам сторов (App Store 5.2.1, Google Play IP policy) и претензии правообладателя; «конкуренты пока живы» — не доказательство безопасности. Проверять как обычный знак: регистрация, сходство, классы/территория, риск путаницы; спорное — юристу. Имя, мимикрирующее под официальную аффилиацию (-dex→Pokédex, poke-/pika-), — стоп-флаг.
- Реальные TM-блокеры — **не-франшизные зарегистрированные знаки в НАШИХ классах 9/42** (пример: Rapiscan/«Certscan» — вот это стоп). Два риска РАЗДЕЛЬНО: судебный (классы/территория) и **store-takedown** (Play принимает жалобу по любой нац. регистрации, классы смотрит нестрого — практически опаснее).
- Обратная сторона: свободно ли имя для НАШЕЙ регистрации в 9/42.

## 4. Скоринг финалистов (таблица 1-10, стопы — только фатальное)

**Принцип: идеальных имён почти не бывает.** Задача скоринга — не отсеять всё, а выдать топ-3 лучших ДОСТУПНЫХ с честным списком недостатков и **митигацией** для каждого. Пустой результат = провал прогона, а не «высокие стандарты».

**Жёсткий стоп (только это):** живой зарегистрированный TM в классах 9/42 на основных территориях (US/EM/GB) у активного игрока · прямой тёзка-конкурент в той же нише стора · негатив/непроизносимость в английском (US+tier-1).

**Всё остальное — штрафные баллы + обязательное поле «митигация»**, например: домен .com занят парковкой → «выкупить или взять .app»; хэндл занят → «вариант get{name}/{name}app»; spelling-риск → «закрепить написание в каждом видео»; SERP частично грязный → «строить сущность brand+category (паттерн PSTR Collage)»; проблема в языке второстепенного гео → «учесть в локальных крео».

| Критерий | Операционализация |
|---|---|
| Голосовой CTA | «Search X in the App Store» — диктуется в видео без запинки |
| Spelling-тест | услышал → написал верно с 1 раза (Slabb/Slab — минус) |
| Запоминаемость | вспомнят через час; есть образ/смысл для ЦА |
| Сленг/фит ниши | значит ли что-то для аудитории |
| SERP ownability | сможем занять «имя» или хотя бы «имя app» за 2-3 мес |
| Стор-чистота | автосаджест/поиск стора не уводит к чужим |
| Домены/хэндлы | .com/.app/@tiktok — свободны или выкупаемы |
| TM-свобода | п.3 |

## 5. Бюджет символов (обоим сторам лимит 30)

- Title: `Brand - Keyword Phrase`, показывать счётчик `26/30`. Бренд ≤10 симв., иначе ключам не хватает.
- Subtitle ≤30: добирает ключи, НЕ повторяя слова title.
- iOS keyword field 100 байт: без пробелов, без повторов слов из title/subtitle.
- Для каждого финалиста — готовая пара Title/Subtitle с счётчиками.

## 6. Портфель и family-стратегия

- Спросить: серия брендов в одном стиле или независимые? (У юзера сложились PSTR/PULLR — это наблюдение, не правило.)
- Каннибализация: если ниша пересекается со своим продуктом — развести позиционирование и title-ключи (эталон: Pullr «широкий scanner» vs Slabb «grading/value», title-ключи не дублируются).
- Запасной аэродром: если короткое имя частично грязное — фиксировать «brand + category» как поисковую сущность (паттерн «PSTR Collage») и вести все CTA на неё.

## 7. Человеческий тест (перед финальным решением)

Продиктовать топ-2 имени 5 людям из ЦА голосом: пусть напишут (spelling) и через час назовут (recall). 15 минут, ловит то, что не ловят таблицы.

## 8. Зафиксировать решение

В доссье: почему выбрали (2-3 строки) + **триггеры пересмотра** через 2-3 месяца: brand query не растёт / выдача грязная / brand-кампания неэкономична / юзеры путаются в отзывах → возвращаемся к ребрендинг-решению по этим данным.

## 9. Формат выдачи

**Финальная таблица — топ-10 по убыванию** (не топ-3): колонки # | Имя | черновик Title (счётчик) | ключевой плюс | ключевой минус | митигация | статус (чист / флаг / нужна доп.проверка). Ранжирование — по совокупности чистоты + звучности + нишевости + дифференциации. Идеального часто нет, поэтому 10 вариантов с честными изъянами полезнее 3 «безупречных» — у пользователя должен быть выбор с пониманием компромиссов. Под таблицей — 2-3 строки на топ-3 «почему именно этот» + явное предупреждение о перегруженных корнях ниши (напр. «-Vault» в TCG). «Все плохие, ищи ещё» без ранжирования — не результат.
