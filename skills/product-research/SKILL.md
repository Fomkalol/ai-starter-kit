# Product Research

Оркестрация глубокого ресерча продукта параллельными субагентами. Итог — доссье-файл с вердиктами, не чат-простыня.

## Шаг 0 — Intake

Выведи ответы из запроса и доступных данных. Одним сообщением спроси только недостающее, что меняет запрошенный результат; вопросы по неприменимым блокам пропускай:

1. **Продукт**: новый (идея/ниша, 1-2 фразы) или существующий (App Store ID, Play package id, сайт)?
2. **Что нужно**: полный ресерч / только нейминг / только конкуренты / только TM-проверка? (выведи из запроса; узкую проверку не расширяй до полного ресерча)
3. **Портфель**: есть ли свои приложения в этой же нише (каннибализация)? И family-стратегия: серия брендов в одном стиле или независимые?
4. **Гео-приоритеты**: основное — US + tier-1 (по нему veto-решения и спрос); гео текущего трафика (PH/ID/BR/MX…) — второстепенные: проверяются, но проблемы там = флаги, не стопы.
5. Если нужен нейминг — есть ли кандидаты, или генерить с нуля (по умолчанию: сгенерить 20-30 → отфильтровать).

Создай рабочую папку: `product-research/<slug>/` в текущем проекте (или спроси, куда). Все результаты — туда.

## Шаг 1 — Fan-out субагентами

Запускай только выбранные блоки. Независимые проверки выполняй параллельными агентами, когда среда это поддерживает и разрешает; иначе последовательно. Готовые проверенные промпты и обходы блокировок: **references/subagent-prompts.md** (прочитай перед запуском).

**Распределение работы:**
- Агенты наследуют модель текущей сессии. Другую модель выбирай только по прямому указанию пользователя.
- Генерацию имён (блок A) и финальный синтез/скоринг делает основная сессия.
- Механические проверки волны 1 (домены/стор/хэндлы) можно разделить между независимыми агентами по группам кандидатов с учётом ограничений RDAP.
- Проверки волны 2 (товарные знаки, конкуренты, спрос) поручай агентам по соответствующим направлениям.
- **Переиспользуй, не перезапускай**: при повторном прогоне в той же нише competitors/demand не меняются день ко дню — бери прошлые результаты, трать токены только на новые имена (волна 1+2 нейминга).

**Нейминг — двухволновой (cheap-first):** волна 1 — генерация + дешёвые фильтры ВСЕМ кандидатам (домены, стор-поиск, SERP, хэндлы, кросс-язык — минуты); волна 2 — TM и глубокий SERP только 3-5 финалистам. Не жечь TM-проверки на 30 имён.

| Блок | Что делает | Когда |
|---|---|---|
| A. Naming | генерация 20-30 + скоринг по рубрике → **references/naming-rubric.md** | если нужен нейминг |
| B. Cheap filters | RDAP-домены + поиск в сторе (iTunes Search API + Play) + соцхэндлы (@tiktok/@ig) + кросс-язычный чек по гео | волна 1, все кандидаты |
| C. Competitors | топ ниши: листинги, рейтинги, загрузки, revenue, сайты, ASO-ключи | полный ресерч или запрос о конкурентах |
| D. Brand collisions | Google SERP по финалистам: кто владеет, отнимаемо ли, «имя+app» как fallback | волна 2 |
| E. Trademark | TMview: классы 9/42; похожие знаки; судебный риск и store-takedown риск РАЗДЕЛЬНО | волна 2; для существующих — по флагу |
| F. Demand/Geo | Keyword Planner (gads MCP): объёмы+CPC по гео, US первым, % от US. **+ trends MCP**: interest_over_time (растёт/падает ниша), related_queries (смежный спрос), interest_by_region (гео) — динамику Keyword Planner не показывает | если gads/trends доступны |
| G. Reviews/Voice | существующий продукт: iTunes RSS отзывы + (если есть UBT-база) топ TikTok-комменты | существующие продукты |

Правила:
- Каждому агенту: «финальный текст = данные для меня, не сообщение юзеру», по-русски, факты — только проверенные фетчем, «не выдумывай номера регистраций/цифры».
- Агентам блоков C/D полезно загрузить скилы `competitor-profiling` / `aso` через Skill tool; блоку A — `marketing-psychology` (виральность/запоминаемость).
- Инструменты деградируют грациозно: нет appstorespy → открытые страницы сторов (с браузерным UA); нет gads → пропусти блок F с пометкой в доссье.

## Шаг 2 — Синтез

Когда все агенты вернулись — собери доссье по шаблону **references/dossier-template.md** в `product-research/<slug>/dossier-<дата>.md`. Ключевое:

- **Вердикты, не пересказ**: каждое имя — балл + недостатки с митигациями; каждый риск — вероятность и цена. **Рекомендация обязана быть всегда** — топ-3 лучших доступных, даже если все с изъянами (rubric §4/§9); «всё отсеялось» — не результат.
- **Каннибализация портфеля** — отдельный раздел, если ниша пересекается со своими продуктами (пример: Slabb развели с Pullr через grading-позиционирование).
- **Данные конфликтуют** (гео/персонализация SERP, разные сторфронты) — покажи оба значения и источники, не усредняй молча.
- Конкретные next steps списком (что руками: ASC/Play Console/EUIPO с классами и владельцем-юрлицом; что кодом).
- При нейминге: рекомендация человеческого теста (5 людей, диктовка → spelling/recall) + «почему выбрали» и триггеры пересмотра через 2-3 мес (rubric §7-8).

Покажи пользователю краткую выжимку в чате (вердикт + топ-3 находки + риски) со ссылкой на файл доссье. Не вываливай доссье целиком.

## Известные грабли (проверено в бою)

- `tmview.euipo.europa.eu` не резолвится — рабочий хост `www.tmdn.org`, POST `/tmview/api/search/results`. USPTO TESS закрыт — покрывается через TMview (офис US, задержка пары дней на свежие заявки).
- Play/App Store/WordPress-сайты часто отдают 403 без браузерного User-Agent — всегда слать UA-строку Chrome.
- Play-листинг может отдавать 404 при снятом с публикации приложении — это не «нет такого пакета».
- iTunes отзывы: `https://itunes.apple.com/{cc}/rss/customerreviews/id={ID}/sortBy=mostHelpful/json` — пробовать несколько сторфронтов (us, gb, au, ph...), большинство пустые.
- Рейтинг из iTunes Lookup (`itunes.apple.com/lookup?id=`) — всемирный vs сторфронт-специфичный различаются; фиксируй какой берёшь.
- Google Ads Keyword Planner через MCP бывает медленный/висит — перезапросить, не считать отказом.
